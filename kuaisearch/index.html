先把定位说清楚

它不是「一个算法」，
而是一条流水线加一把尺子

KuaiSearch 的主体是数据集：3.3 亿级交互日志的脱敏发布。仓库里的代码是基准实现——把工业搜索的三个阶段各自跑通一批代表性方法。

所以「这个算法怎么工作」的正确读法是：工业电商搜索的三段式流水线怎么工作，以及这份数据为每一段提供了什么监督信号。下面 16 页就按这个顺序讲。

为什么难

电商搜索的三个结构性难点

Query 侧

短、糊、多意图

用户打的是「鼠标」「白鞋」，不是完整商品描述。1–2 字 query 的一级类目归一化熵高达 0.419；即便超过 10 字，品牌熵仍稳定在 0.58–0.68——再长的 query 也说不清品牌偏好。

Item 侧

标题是关键词垃圾场

商家为了曝光往标题里塞词，品牌、属性、类目以任意顺序堆叠，语义序被破坏，判别式表征模型直接受害。

User 侧

同一 query，不同人

预算、属性偏好、使用场景全不一样。论文用 JS 散度验证：用户近期兴趣与自己历史的散度显著小于与大盘的散度——个性化信号真实存在。

数据实证的词表不对称：商品标题词表 413,301 个词，query 词表仅 116,897 个（3.54 倍）。在 303 万条「点击过的 query–标题」对里，16.92% 完全零词重叠，33.48% 重叠率不足一半。
——这一条直接判了纯字面匹配的死刑，也解释了后面 BM25 为什么打不过向量召回。

  • Amazon 系：query 是从商品元数据启发式拼出来的，且滤掉了冷启用户与长尾商品——分布已经不是真实搜索了。
  • JDsearch：真实 query、保留长尾，但文本全部匿名化，LLM 完全没法用。
  • Qilin：有明文，但场景更接近内容浏览而非商品搜索，且只有一天的交互。
  • 共同缺陷：只覆盖流水线的单一阶段，无法在同一份真实数据上串起召回→排序→相关性。

KuaiSearch 的三条硬承诺：不做流行度过滤（长尾商品与冷启用户全留） · 文本明文保留 · 三阶段共用同一份真实域数据。

脱敏做法

所有 id 换成不可逆随机 id；年龄聚合成 7 档；地理只保留到省；绝对时间戳换成相对时间索引——所以数据里只有 time_index 没有真实日期。

KuaiSearch-Lite

论文所有实验都跑在 Lite 上。抽样单位是用户而不是单条请求——随机取 10.2 万用户的完整一个月记录，从而保住行为序列的时间连续性与 query→曝光→点击→购买的关联。

总览

一次搜索请求，走完这三关

三个阶段在仓库里是三份互不依赖的代码：recall/ · relevance/ · ranking/，各自独立训练与评测。

阶段一 · 召回

三种范式，回答同一个问题：
怎么在千万商品里快速捞出候选

范式 A

字面匹配

建倒排索引，按词频打分。BM25、DocT5Query。快、可解释、零训练，但被词表不对称卡死。

范式 B

向量检索

query 与商品各编成一个向量，用近似最近邻搜。DPR-ADE/SDE、BGE。本文的赢家。

范式 C

生成式检索

把商品编成「语义 ID」，让模型直接把 ID 生成出来。DSI、LTRGR、LC-Rec。最新潮，本文里最吃亏。

评测口径

R@K = (1/|S|) · Σ_s |TopK(s) ∩ I_s| / |I_s| HR@K = (1/|S|) · Σ_s 1[ |TopK(s) ∩ I_s| > 0 ]

I_s = 该次搜索请求中被点击或购买的商品集合。切分方式是按时间：最后一天做测试集，之前全部做训练。

公共设定

  • 商品侧输入只用标题，保证各方法公平。
  • 只保留至少有一次点击或购买的请求。
  • 向量方法 query/标题都截到 64 token，内积相似度，Faiss IndexFlatIP 精确检索。

召回 · 范式 A

BM25，以及用生成来给它「补词」

BM25：词频打分的经典形式

score(q,d) = Σ_t IDF(t) · f(t,d)·(k₁+1) ───────────────────────── f(t,d) + k₁·(1−b+b·|d|/avgdl)

f(t,d) 是词频，分母那一项做长度归一，防止长标题因为词多而占便宜——这在标题堆关键词的电商场景尤其关键。

本文设定：jieba 中文分词，k₁ = 1.2，b = 0.75（标准值）。
实现见 recall/BM25/BM25/sparse_retriever/sparse_retrieval_models/bm25.py

DocT5Query：把问题反过来解

既然 16.92% 的点击对零词重叠，那就在索引侧补上用户可能会打的词。

  • 用训练集训一个 mT5-base，学「商品标题 → 用户 query」的反向映射；
  • 给每个商品生成 10 条伪 query；
  • 把伪 query 拼到标题后面，一起进倒排索引；
  • 检索时仍然是原味 BM25——推理零额外开销，代价全付在离线。

recall/BM25/doc2query.py（生成）→ recall/data/construct_i2q.py（构造 item→query 训练对）

召回 · 范式 B

DPR 双塔：把匹配变成向量点积

两个 BERT 编码器，各取 [CLS] 位的隐状态当向量。商品向量可以离线全量算好，线上只编码 query，剩下的交给 ANN 索引。

q = Enc_q(query)[CLS] d = Enc_d(title)[CLS] sim(q,d) = qᵀd ← 内积 L = −log exp(sim(q,d⁺)) ───────────────────── Σ_j exp(sim(q,d_j))

分母里的 d_j 取同 batch 内其他样本的正例作负例（in-batch negatives）——一个 batch 里 N 个样本互相当负样本，等于免费拿到 N−1 个负例。

recall/dpr/train.py:87–123（DualEncoder + calculate_dpr_loss）

ADE vs SDE：一个开关的差别

ADE（非对称）query 与 item 各用一套参数；SDE（对称）两侧共享同一个编码器。代码里就是 share_encoder 一个布尔量。

结果 SDE > ADE。原因是共享参数把两侧强行拽进同一个向量空间，避免了两个独立编码器各自漂移、空间错位。

为什么它在本文赢了

向量匹配不依赖字面共现，正好对症「query 短、标题脏」这个病。而 BGE-base-zh 经过微调后全指标最优——预训练中文表征 + 电商域适配，是这份数据上性价比最高的一条路。

召回 · 范式 C · 第一步

生成式检索：先给每个商品发一个「语义身份证」

生成模型没法直接吐出 1800 万个 item_id。RQ-Kmeans（残差量化聚类）把一个 512 维标题向量压成 3 个整数，且语义相近的商品共享前缀。

召回 · 范式 C · 第二步

把「检索」改写成「生成一串数字」

DSI：seq2seq 直接生成 ID

mT5-base 学两件事：索引任务（标题 → 语义 ID）让模型把语料背进参数里；检索任务（query → 语义 ID）学真实映射。推理时 beam search，num_beams=50 一次吐 50 个候选。

Trie 约束解码：不许它编造

自由生成会产出不存在的 ID。做法是把全部合法 ID 插进一棵前缀树，每步解码时查树拿到合法后继 token，其余位置 logits 全打成 −inf。

allowed = trie.get_next_tokens(已生成前缀) scores[不在 allowed 的位置] = −inf

recall/GR/train.py:34–78（Trie + TrieConstraintLogitsProcessor）

LTRGR：在生成损失上加一层排序损失

纯生成损失只教「正确答案的概率要高」，不教「要比错的高」。LTRGR 补一个 margin hinge：

s⁺ = 正确 ID 的序列对数概率 s⁻ₕ = 逐位取最大的「最强负例」 s⁻ᵣ = 随机负例 L = relu(s⁻ₕ − s⁺ + 0.25) + relu(s⁻ᵣ − s⁺ + 0.25) + 1000 × L_gen

recall/GR/trainer.py:24–55。λ=1000 这个量级说明生成损失仍是主项，排序损失只做微调。

注意 LTRGR 不是从零训练——代码里它加载 DSI/best_model 继续训 5 个 epoch，是个后置精调阶段。

召回 · 结论

向量赢了，生成式在这份数据上没打过 BM25

排名

BGE-base-zh（微调） > DPR-SDE > DPR-ADE > BM25 ≈ DocT5Query ≈ DSI / LTRGR / LC-Rec

Embedding 类在几乎所有 Recall@K 与 HR@K 上领先；生成式类只与字面匹配打成平手。

3.54×标题词表 / query 词表 —— 这就是 BM25 的天花板

生成式为什么吃亏（论文给的解释）

  • query 模糊且多意图：一个 query 对应多个正确 ID，自回归解码却被迫押注一条路径。
  • 商品库过大且长尾：1860 万个 ID 要背进参数，长尾商品在训练集里出现次数太少，根本没背下来。
  • 商品文本噪声大：语义 ID 由标题向量聚类而来，标题脏则码本脏，前缀树的层次结构跟着失真。

这不是说生成式检索不行，而是说它在真实电商长尾上的短板被这份数据暴露出来了——这正是数据集的价值：让乐观的结论露出破绽。

阶段二 · 相关性

四级人工标注，是这份数据最贵的部分

分含义样本数占比
0完全不相关，类目或属性明确冲突6,09513.13%
1弱相关，近似类目但满足不了意图8,83419.03%

2 分和 3 分合计占 67.84%——数据集刻意不由「一眼相关/一眼无关」的水样本主导，模型必须能分辨类目边界与属性级约束这种细活。

标注质量控制

  • 每对 query–商品由 3 名有电商搜索一线经验的标注员独立盲标；
  • 每个标签必须附书面理由，逼标注员按规范而非直觉判断；
  • 三人一致率 93%，Fleiss' κ = 0.89（近乎完美一致）；
  • 小分歧走多数投票，大分歧先集体对齐口径、再独立重标一轮。

建模时怎么用

随机 10% 做测试。只有 3 分算正例，0/1/2 全算负例，退化成二分类。指标用 ROC-AUC（整体排序质量）+ PR-AUC（类别不均衡下识别正例的能力）。

相关性 · 三种建模

交互发生得越早，判得越准

Bi-Encoder

双塔 · 各编各的

score = cos( E(query), E(item) )

query 与商品分别独立编码，最后才用余弦相似度撞一下。可以离线建库，最快，但两侧在编码时互相看不见。

BGE-Base-zh / BGE-Large-zh

Cross-Encoder

拼接 · 联合编码

[CLS] query [SEP] item [SEP] ↓ BERT 全层自注意力 → 二分类 head

两段文本拼成一条进模型，每一层注意力都能做 token 级对齐。慢，但准。只能在候选集小时用——所以它在流水线里排在召回之后。

BERT-Chinese / BERT-Multilingual / XLM-RoBERTa

LLM 生成式判别

问它一句 yes / no

<Instruct>: … <Query>: 眼影盘橘朵 <Document>: Judydoll橘朵单色… ↓ 单次前向 p(yes) = softmax([l_no, l_yes])[1]

不做自回归解码，只取最后一个位置上 yes / no 两个 token 的 logits 做二元 softmax，拿 p(yes) 当相关性分。

relevance/GR/utils.py:24–32（compute_p_yes）

LLM 侧的训练细节

LoRA 微调，r=8、α=32、dropout 0.1，挂在 q_proj k_proj v_proj o_proj gate_proj up_proj down_proj 七个投影上。训练时 label 只在答案 token 上算损失（前面全 −100 屏蔽）。

一个工程巧思

Qwen 模板里 assistant 段直接写死 <think>\n\n</think> 空思维块——强制关掉推理模式，让下一个 token 必然是答案位。判别任务因此退化成一次前向，吞吐与 Cross-Encoder 同量级。

阶段三 · 排序

八个 CTR 模型，共用同一根特征拼接向量

输入向量怎么拼出来

x = [ query_emb 512 ← BGE-small-zh-v1.5 user_sparse 56 ← 性别 8 + 年龄 16 + user_id 32 history_encoding 144 ← 近 20 次点击的池化 item_sparse 144 ← item_id 32 + 三级类目 16/32/64 title_emb 512 ← BGE-small-zh-v1.5 ]

所有模型特征集完全一致，差别只在这根向量之后怎么建交互。优化器 Adam，lr 1e-3，weight decay 1e-5，BCE 损失，batch 20,000，最多 20 epoch。

ranking/models.py · 按时间切分：最后一天做测试，模拟真实上线

DIN：历史行为不该被平均

DNN / W&D / DCN 都对 20 个历史商品做 mask 均值池化——不管你搜什么，用户画像都是同一个。DIN 换成按目标商品动态加权：

w_j = MLP([ e_j , v_A , e_j−v_A , e_j⊙v_A ]) u = Σ_j w_j · e_j

四元组拼接同时喂进原值、目标、差、积，让 MLP 自己学相关度。注意实现细节：不做 softmax、不除以分母——权重和不归一，于是「历史里有多少个相关商品」这个强度信息被保留下来（这是 DIN 原论文的设计）。

ranking/models.py:36–72、195–197

DCN v1 vs v2：一个秩的差别

v1: x_{l+1} = x₀ · (wᵀx_l) + b + x_l v2: x_{l+1} = x₀ ⊙ (W x_l + b) + x_l

v1 的 w 是向量（秩 1，整层被压成一个标量再放大）；v2 换成矩阵 W，每个维度都能独立组合——表达力的差距就体现在 0.6194 → 0.6239。
