背景 01要被替掉的东西

传统搜索是一条漏斗，而漏斗有两个治不好的病

多级级联架构（MCA）用「由粗到细」换响应时间：召回扫全库 10⁹，粗排收到 10⁴，精排只看 10²。

论文给出的反证实验很直接：线上把 MCA 的精排整级摘掉，只留召回+粗排，订单量掉 39.14%。 而纯生成的 OneSearch 能打平整条链路 —— 说明它一个模型同时具备了召回的「全」和精排的「准」。
背景 02生成式检索的地基

语义 ID：把一亿个商品塞进一个 5 token 的词表

生成模型没法「生成」一个 64 位商品 ID。必须先把商品变成一小段有语义、有层次的离散 token。

机制

由粗到细的编码链

商品内容 → 一个稠密向量 → 逐层残差量化 → 一串码本下标。同一层码字相同的商品，共享该层级的语义。

<a_1806><b_200><c_403><d_52><d_313>

前三位（teal）是 RQ 层：类目、大属性这类共性。
后两位（amber）是 OPQ 层：区分「像但不是同一个」商品的个性。

于是搜索变成

一个 seq2seq 任务

输入拼成一句话：用户 ID、当前 query、query 的 SID、最近搜索序列、历史点击序列、长期行为向量。

𝓘 := 𝓜( uid, q, SIDq, Seqq, Seqshort, Seqlongemb, 𝒰 )

输出用 beam search 展开 512 条，每条就是一个商品 SID。beam 的得分顺序，直接就是展示顺序 —— 排序不再是一个独立阶段。

线上骨干用的是 BART-base 这类 encoder-decoder（论文说线上参数量至少是 BART 的 100 倍，未公开具体数字）。 选 encoder-decoder 而非 decoder-only，理由是结构上的训练/推理加速更成熟，能扛住搜索的延迟预算。
背景 03为什么不能照搬推荐

电商搜索的三道坎

OneRec（视频推荐）、OneSug（query 联想）都跑通了，但搜索不一样：它的输入和输出一边是开放词表，一边是封闭词表。

坎 01

商品文本又长又脏

商家为了曝光会硬塞无关关键词，属性堆叠导致语义顺序很弱 —— 品牌、材质、类目出现在哪里全凭运气。编码器很容易被带偏。

坎 02

强相关性约束

query 通常只有 2–3 个词，错一个属性就是事故。可 SID 天然是「共享化」的，越分层越容易把核心属性抹平 —— 这是一对直接的矛盾。

坎 03

意图藏在行为里

「银戒指」到底是买给自己还是买给对象？只有把 query 和用户长短期行为一起看才知道。传统精排靠上千维特征硬拟合，几乎没有推理。

这三道坎，正好对应 V1 的三个模块

坎 01 + 坎 02 → KHQE 关键词增强分层量化编码（把核心属性顶上来，再用 RQ+OPQ 同时保住共性和个性）
坎 03 → Mu-Seq 多视角行为序列注入 + PARS 偏好感知奖励系统

OneSearch V1总览

三个模块，一条流水线

V1 要解决的是「能不能用一个生成模型把整条搜索链路替掉」。答案是能，而且更省。

模块 A · 表示

KHQE

关键词增强的分层量化编码。先把 query 和商品对齐到同一个表示空间，再用 RQ-Kmeans 抓层次 + OPQ 抓残差 得到 5 位 SID。

模块 B · 输入

Mu-Seq

三路注入用户行为：行为构造的 user ID、prompt 里的显式短序列、模型内部的隐式长序列向量。

模块 C · 训练

PARS

三阶段 SFT（语义对齐 → 共现同步 → 用户个性化）+ 自适应奖励系统 + listwise DPO 偏好对齐。

KHQE · 第 1 步模块 A

先让 query 和商品住进同一个表示空间

如果 query 向量和商品向量各说各话，后面量化出来的 SID 就没有可比性。所以第一步是训一个对齐编码器。

数据

先挖高质量协同对

用 ItemCF、Swing 从真实搜索日志里挖 query2query、item2item、query2item 三类对，再用余弦相似度 > 0.6 过一遍，保证内容确实相关。

每条内容喂进去的是：query 文本、商品标题、价格、关键词、图片 OCR，加上点击 / 加购 / 成交的统计特征。编码器是蒸馏过的 BGE。

注意这里的设计意图：协同信号（谁和谁一起被点）负责决定「哪些该靠近」，语义模型负责把它们真的拉到一起。 纯语义相似的两个商品，如果从没被一起交互过，不会被强行拉近。
五个 loss 各管一件事

对齐目标

𝓛align = λ₁𝓛q2q + λ₂𝓛i2i + λ₃𝓛q2i + λ₄𝓛rank + λ₅𝓛rel
  • q2q / i2i 对比损失 —— 把协同相似的同类对拉近
  • q2i 对比损失 —— 让表示反映真实业务关系
  • rank margin 损失 —— 区分「曝光 / 点击 / 成交」这几档强度，不是简单的正负二分类
  • rel 困难样本纠偏 —— 相似度卡在阈值附近的对，用大 LLM 打一个相关性分，让 BGE 去拟合这个分
KHQE · 第 2 步模块 A

核心关键词增强：把埋在噪声里的属性顶上来

做法极简单，效果却出奇地好 —— 这是全篇性价比最高的一个 trick。

怎么做

18 类属性 NER + 向量平均

用 NER 定义 18 类结构化属性（实体、修饰、品牌、材质、风格、功能、场景、受众、颜色、价格、型号、系列、季节、花型…）， 从过去一年的点击 query-item 对里按 PV 降序挑出高频词作为核心关键词。

商品侧用 Qwen-VL 识别关键词；query 侧用 AC 自动机 实时匹配（毫秒级，能上线）。

eoq = ½ ( eq + 1/m Σ eik )    eoi = ½ ( ei + 1/n Σ ejk ) // 原始向量与核心关键词向量各占一半

CUR＝码本利用率，ICR＝独立编码率（多少商品拥有唯一 SID）。两个都是越高越好。

反直觉 · 别在所有层做 balanced kmeans

OneRec-V1 的做法是全层做均衡聚类逼高利用率。但电商商品属性粒度太细，早期就强行均分会导致层次聚类崩塌 —— 表里最后一行，CUR 总利用率反而从 1.64% 掉到 0.51%。

正确做法是只在第三层做均衡：前两层放任它按语义自然聚，第三层负责把挤在一起的相似商品拆开。ICR 从 43% 直接跳到 68%。

KHQE · 第 3 步本篇最核心的算法

RQ-OPQ：用两种量化，分别承担共性与个性

RQ 天生擅长层次，但它会把最后那点残差直接扔掉 —— 而残差里装的恰恰是「这个商品和它邻居的区别」。

两个附带结论：

① RQ-Kmeans 全面优于 RQ-VAE —— 这与 OneRec 的结论一致，所以 V1 直接放弃了 VAE 路线。

② 别加太多 OPQ 层。消融显示 OPQ(4/256) 反而掉 2.4%，把三层聚类结果也一起 OPQ 化（4×4/256）直接掉 24% —— 序列一长，层次特征就被淹没，大量商品重新挤回同一个 SID。2 层是甜点。
Mu-Seq模块 B

用户行为的三条注入通道

难点在于长序列可以到 10³ 量级，硬拼进 prompt 是不可能的。V1 的解法是按「时效性」分流。

为什么 user ID 要用行为构造

随机哈希 ID 是无效的

TIGER 的做法是把用户哈希到固定词表。问题是行为完全不同的两个人可能拿到同一个 ID，这种 ID 不携带任何语义。

V1 改成对用户点击过的商品 SID 做加权求和再取整，权重 λᵢ = exp(√i)/Σexp(√i) 让近期行为占比更高。短序列和长序列各生成 5 位，拼成 10 位 user ID。

冷启动用户？用该 query 下点击最多的商品按 PV 倒排，当作默认行为序列。

消融（相对 OneSearch）成交 HR@350点击 HR@350

短序列贡献最大。滑窗增强指的是在 Seqshort 上滑动取子序列 + 下一个商品当标签（最大窗长 5）， 既教模型捕捉兴趣漂移，也顺手解决了新用户历史太短的问题。

PARS · 训练模块 C

三阶段 SFT：从「认字」到「懂人」

BART 预训练时见过的是自然语言，没见过 <a_3558>。所以必须先教它 SID 是什么意思，再教它怎么用。

Stage 1

语义对齐

让 SID 和文本互相翻译，并且都能落到正确类目。

  • query ↔ SID 双向
  • 商品标题 ↔ SID 双向
  • query / 商品 → 类目
  • SID → 类目

前两个任务对齐符号，类目任务保住相关性。

Stage 2

共现同步

暂时忽略用户，只学 query 和商品之间的内在语义与协同关系。

  • query ↔ item（文本层）
  • SIDq ↔ SIDi（符号层）

语料来自海量线上交互，学的是「什么 query 该出什么货」。

Stage 3

用户个性化

把用户信息全部拼进来，输入格式与线上推理完全一致。

[ uid, q, SIDq, Seqq,
  Seqshort, Seqlongemb ] → SIDitem

滑窗增强就用在这一阶段。V2 后面动刀的也正是这一阶段。

更新节奏是分层的：多阶段 SFT 每周跑一次；带奖励模型的 RL 每天跑；基于真实用户交互的偏好对齐尽量做到准流式。 作者还提了一句 —— 奖励模型那部分其实每周跑也行，收益不大，除非赶上双 11、618 这种大促。
PARS · 对齐模块 C

自适应奖励 + listwise DPO

SFT 只会拟合「用户点了什么」，学不会「为什么这个比那个好」。偏好对齐要补的是这一课。

第 1 层 · 行为分档

六档权重

把交互按强度分成六档，基础权重 λ = [2.0, 1.5, 1.0, 0.5, 0.2, 0.0]：

  • 搜索场景成交 → 推荐场景同类目成交 → 点击
  • 曝光未点 → 同类目未曝光 → 其他类目随机
第 2 层 · 后验校准

CTR / CVR 的偏差修正

裸 CTR 不能直接用：只曝光过 1 次且被点了的新品 CTR＝100%；真正的爆款反而因为被 MCA 塞到各种次优 query 下而 CTR 偏低。

CntT = log( (Cntpos+10)(Cntclk+10)(Cntorder+10) ) Ctri = log(Cntclk+10) / CntT Cvri = log(Cntorder+10) / log(Cntclk+10) // 调和平均后乘以档位权重 r(q,i) = 2λ · (Ctr·Cvr)/(Ctr+Cvr)
第 3 层 · 奖励模型

三塔 SIM，不用 GRPO

基于 SIM 的三塔结构，分别学 CTR / CVR / CTCVR，各用 BCE。相关性分单独加进来并放大 10 倍权重：

Rscore = λ₁·CTR + λ₂·CVR + λ₃·CTCVR + 10·λ₄·SRel

与线上精排的关键区别：只吃 OneSearch 能拿到的那几个特征（uid、query、行为序列、画像），而不是上千维 —— 保证输入空间对齐。

作者明确说明：这里没用 GRPO 系（ECPO/GBPO），因为它们在电商搜索里容易生成大量不相关 SID。

第 4 层 · 优化

listwise DPO ＋ NLL 混合

𝓛 = −𝔼[ log σ( log Σl exp( rwΔ·max(0, r̂(x,iw) − r̂(x,il) − δ) ) )     + α·log πθ(iw|x) ]

一个正样本对多个负样本；rwΔ = 1/(r(q,i⁺) − r(q,i⁻))， 偏好差距越小，权重越大，逼模型去分辨细微差别。后半段的 NLL 项防止对齐把 SFT 学到的东西冲掉。

两阶段的用意：先用奖励模型重排的样本训练，把线上精排（上千特征、更大模型）的排序能力蒸过来； 但奖励模型本身是拿 MCA 日志训的，天花板就在那儿。所以第二阶段改用纯真实用户交互继续训，才有机会超过 MCA。

OneSearch V2V1 撞到的墙

三个瓶颈，恰好是「理解不够深」的三种形态

瓶颈 01

复杂 query 理解不足

「室内健身器材」可以是跑步机也可以是哑铃，但绝不是山地车。还有否定式（「缓解疲劳，不要保健品」）和疑问式（「游泳需要准备什么」）。

V1 是单次前向直出，虽然 SFT Stage 1 有类目监督，但对这种歧义 query 依然只能做浅层匹配。

这类 query 占 1/3 PV，却只贡献 8% 转化。

瓶颈 02

个性化意图推理不足

V1 靠周期性更新拟合历史共现，本质是 log-fitting。用户搜「当季鲜花」，模型应该先推理当前季节、什么在开、再避开用户过敏的品种 —— 哪怕那个品种历史转化很高。

LLM 用显式 CoT 能做到，但多生成的 token 在搜索的延迟预算里是不可接受的。

瓶颈 03

奖励系统脆弱且有分布偏差

奖励模型是拿历史日志训的，采样只覆盖一小撮用户，容易 reward hacking，也跟不上新出现的 query 和意图。

结果就是过拟合到狭窄的历史偏好，反过来强化了信息茧房和长尾稀疏 —— 这正是当初要摆脱 MCA 的毛病。

V2 的三个回应

瓶颈 01 → 思维增强的复杂 query 理解（关键词式 CoT）
瓶颈 02 → 推理内化的自蒸馏（把 CoT 塞进权重，推理时零成本）
瓶颈 03 → 行为反馈偏好对齐（扔掉独立奖励模型，复合奖励 + TPMA-GRPO）

V2 · 前置实验一个值得记住的负面结论

多模态 SID 打不过单模态

商品明明有图有视频，为什么把它们编码进去反而更差？

多模态uniecs200M94.62%0.23680.1007

109M 的 bge-base 打赢 2B 的 qwen3-vl。分开编码再拼接的策略表现最差。

原因

多模态引入的是噪声，不是信息

  • 多张图会给出互斥属性 —— 同一条裙子的不同配色图，编码器不知道该信哪个
  • 冗余属性带来额外偏置 —— T恤有几颗扣子、扣子在哪，模型认真学了，但这跟 query 毫无关系
  • 跨模态表示鸿沟 —— query 天然是纯文本，硬拉到多模态空间反而加大了 query 和商品的距离
V1 的做法其实早就答对了

KHQE 的路线是先用 Qwen-VL 把多模态信息「翻译」成核心关键词，再统一在文本空间编码。 这等于在进入表示空间之前就完成了降噪和对齐。

附带的好处是编码器小（109M），能对用户实时输入的 query 做在线编码 —— 大模型做不到这一点。

V2 · 创新 1思维增强的 query 理解

关键词式 CoT：只要结论，不要过程

完整 CoT 又长又啰嗦，小模型生成不动，而且电商场景其实只关心那几个词。

4 个新 CoT 任务

符号层和文本层都要学

  • query → keywords
  • query_sid → keyword_sid
  • query + 用户 → 个性化 keywords
  • query_sid + 用户 → 个性化 keyword_sid
实际样例
query <cleanfit> + 「18-23 岁男性」+ 最近搜过 哈灵顿夹克 国潮穿搭
→ cleanfit穿搭, 工装牛仔裤, 美式短袖T恤, 微喇牛仔裤男, 冰蓝牛仔裤
注意这个设计的巧妙之处：关键词既是训练语料（教模型理解 query）， 又是推理时可选的输入增强（RAG）， 还是后面自蒸馏里教师端的特权信息。一份数据，三种用途。
V2 · 关键转折一个必须绕开的坑

让模型「说出」思考过程，性能直接腰斩

最自然的想法是：先生成推理关键词，再生成商品 SID。实验结果是灾难性的。

为什么会崩

SID 和文本是两种异质符号

离散 SID（<a_97>）和自然语言关键词（「工装牛仔裤」）在表示上根本不同源。 让一个小模型在同一个自回归序列里先产出一种、再产出另一种，等于要它在两个词表之间来回切换。

作者还引了另一项研究佐证：训练时插入显式推理步骤，本身就可能损害模型的组合泛化能力。

于是问题被重新定义了

关键词放在输入端有用（0.2094 → 0.2139），放在输出端有害。
但放在输入端意味着每个请求都要额外调一次 query 理解模块 —— 线上延迟扛不住。

能不能保住推理带来的收益，却不付推理的代价？
这就是自蒸馏要回答的问题。

还有一个更隐蔽的问题：关键词集合的覆盖面是有限的。 用户搜「酒店必备」，如果关键词只有毛巾、牙刷、剃须刀，模型就永远想不到一次性拖鞋。 把推理内化，反而能挣脱关键词集合的边界。
V2 · 创新 2全篇最漂亮的一招

推理内化的自蒸馏：同一套权重，两种视野

不加参数、不加特殊 token、不改架构、推理时不多生成一个字。

损失函数

只有 KL，没有别的花样

𝓛KL = 1/|𝒱| Σt∈𝒱 KL( softmax(zt(T)/τ) ‖ softmax(zt(S)/τ) ) · τ² 𝓛base = 𝓛CE(z(S), y) + αKL · 𝓛KL

𝒱 是有效（非 padding）token 位置集合。教师 logits 从计算图 detach，教师前向在 torch.no_grad() 下跑， 只有学生这条路径累积梯度。

代码细节：教师和学生序列长度不同（prompt 长度不一样），但输出 token 完全一致， 所以实现里对有效位置做尾部对齐再算 KL。见 joint_sdft_trainer.py。

V2 · 创新 2 续让不对称训练稳下来

三件正则套装：R-Drop + FGM + Focal Loss

强迫学生在更少信息下给出同样自信的预测，代价是 loss surface 在「无关键词输入」附近变得陡峭 —— 输入稍动，输出剧变。

失效模式 1 · 输出不稳

R-Drop

同一个输入用两组独立 dropout mask 走两遍，要求两次输出分布一致：

𝓛R-Drop = ½[ KL(P₁‖P₂) + KL(P₂‖P₁) ]

对称惩罚，逼模型别依赖那些一 dropout 就断的脆弱内部通路。α_R = 0.5

失效模式 2 · 输入不稳

FGM 对抗扰动

第一次反传后，沿梯度方向扰动共享 embedding 层：

radv = ε · ∇e𝓛base / ‖∇e𝓛base‖₂

在 e + r_adv 上再走一次前向反向，梯度累加后还原 e。把每个输入周围的 loss 曲面抹平。ε = 0.6

失效模式 3 · 类别失衡

Focal Loss

SID 词表天然长尾 —— 少数热门 SID 占掉大部分样本。用 focal loss 替换标准交叉熵，压低易分样本的权重。

α = 2, γ = 3

𝓛SDFT = 𝓛CE + αKL·𝓛KL + αR·𝓛R-Drop + 𝓛adv // 𝓛_adv 是扰动输入上的 CE + 加权蒸馏损失（复用同一个 α_KL）

作者的解读：信息不对称造成的不稳定同时体现在三个维度 —— 输入表示脆弱、输出预测抖动、类别分布失衡。 三个手段各治一个，缺一个就有短板。

V2 · 方法论与潜推理路线的对比

为什么不用 Coconut / CODI 那套潜 token？

「把推理压进连续向量」是当前主流的潜推理思路。V2 走了另一条路，并给出了实验依据。

内化策略成交 HR@10成交 MRR@10点击 HR@10
baseline0.20940.10080.2266
(i) special-token 蒸馏0.20920.09990.2335
(ii) CODI 潜向量对齐0.21050.09850.2269
(iii) EMA-mode 教师0.20970.10090.2317
(iv) joint-mode 联合训练0.21560.10160.2348
self-mode（本文）0.21630.10170.2398

CODI 再加投影层（0.2092）、再叠加 KL 蒸馏（0.2084）都没救回来，反而更差。

原因 1

监督粒度不同

自蒸馏在每个 SID token 位置都给学生一份教师的完整输出分布 —— 直接告诉它「关键词把哪些候选码的概率抬高了、哪些压低了」。

CODI 只在单个蒸馏 token 上做隐状态的 L1 回归，其余 SID 位置拿不到任何推理指导。加投影层也补不上，说明短板在监督形式本身，不在模型容量。

原因 2

两个损失互相打架

L1 要把隐状态拉向教师的逐层几何结构，KL 要塑造输出分布。最满足前者的表示，未必最适合后者。

纯 KL 的写法绕开了这个张力 —— 内部表示怎么组织交给模型自己决定，只约束最终该输出什么。

工程上还有个朴素理由：self-mode 不需要改架构、不需要额外参数、不需要特殊解码。 对一个每天扛千万级 PV 的线上系统，这一条的分量不比精度低。
V2 · 创新 3行为反馈偏好对齐

扔掉独立奖励模型，直接用真实交互当奖励

V1 的奖励模型是拿历史日志训的，采样偏差和 reward hacking 是结构性的。V2 干脆不要它了。

复合奖励

三个信号相加

Ritem(oi) = RC&O + RCTR + RRel
  • RC&O 点击/成交分：命中成交集 → Vo，命中点击集 → Vc，否则 0。层级化地表达「购买 > 点击」
  • RCTR 后验转化分：沿用 V1 的校准 CTR，裁剪到 (0,1)，防止高 CTR 但不相关的商品霸榜
  • RRel 相关性分：复用现有相关性系统的四档 —— 3 优秀 / 2 相关 / 1 不匹配 / 0 无关

加法而非乘法，是为了避开奖励稀疏问题，同时让相关性和转化在同一个尺度上可调。

代码里还有一个论文正文没细讲的辅助奖励：format_reward 用正则 ^<a_\d+><b_\d+><c_\d+><d_\d+><d_\d+>$ 校验生成的 SID 格式是否合法，用来约束格式有效性与层次结构。

小提示：论文正文写 Vo, Vc = 3, 4，而 reward.py 里是 v_order=4.0, v_click=3.0。以代码为准 —— 成交权重高于点击才符合设计意图。
为什么电商搜索不能照抄 OneRec-V2

反馈结构本身就不同

(a) 行为是层级递进的。短视频里点赞、关注、转发、评论可以同时发生；电商里必须先点击、才能加购、才能购买。所以不同信号之间的偏好强度差异更清晰、也更该被区分对待。

(b) 相关性是硬约束。用户对「搜的和出的对不对得上」极其敏感，相关性必须和转化联合优化，而不是事后过滤。

线上编排

DPO 打底，TPMA 收尾

两者优化的是互补的东西：listwise DPO 用真实日志拟合用户偏好，GRPO 系靠组内相对优化引导模型生成更符合奖励的样本。

所以线上先跑 listwise DPO 学基础交互偏好，再用 TPMA 平衡多个奖励目标、提升泛化。

批大小：SFT 512 / DPO 2048 / GRPO 256。RL 阶段做流式训练，新 query 和新意图能当天进模型。

TPMA-GRPOV2 第二个核心算法

SID 是有因果层次的，凭什么每个位置分同样的功劳？

标准 GRPO 给整条序列一个 advantage。但「类目对了、细节错了」和「类目就错了」，是完全不同的两件事。

公式

三步走

① 逐位置组内归一化（只和其他 rollout 的同一位置比） Âi,l = (ΔRi,l − meanjΔRj,l) / (stdjΔRj,l + δ) ② 叠加序列级的商品价值优势 Âfinali,l = Âi,l + witem · Âitemi ③ 门控 × 重要性比 × 优势，无 clip 𝓛TPMA = −1/G Σi 1/L Σl gi,l · ri,l · Âfinali,l

① 回答「该生成什么」（结构对不对），② 回答「生成得值不值」（转化价值高不高）。两条信息互不干扰地叠加。

设计意图

为什么前两位权重是 2

前两位是 RQ 的共性编码（类目、大属性），第 3–4 位偏细粒度。生成式检索首先要保证语义相关，所以粗粒度位置的贡献要加倍。

注意代码里 l = L（第 5 位）的权重是 0 —— 最后一位不参与边际奖励，只通过 Âitem 那一路拿到信号。

为什么敢去掉 clip

门控就是天然的正则

标准 GRPO 靠 clip 防止重要性比爆炸。TPMA 里当 g → 0，无论比值多大，该位置的有效梯度都归零。

作者说这与 OneRec-V2 的 GBPO 精神类似，但用结构化门控而非硬截断，稳定性更好。同时会混入额外的 SFT 保持模型不漂。

全景两代对照

V1 建骨架，V2 补大脑

V1 回答的问题

端到端生成能不能替掉整条链路？

能。关键在于 SID 必须同时编码层次共性（RQ）和独特个性（OPQ），行为必须按时效分三路注入， 以及必须有偏好对齐才能补上「排序」这一课。

代价降了 75%，MFU 涨了 8 倍。

V2 回答的问题

不加推理成本，能不能获得推理能力？

能。关键在于推理必须内化而不是外显 —— 让模型说出思考过程会崩，把思考灌进权重才有效。 而信息不对称的自蒸馏，是最省的实现方式。

顺带把奖励模型也扔了，换成可以随时调的复合奖励。

要点如果只记住六件事

可迁移的经验

01

量化要分工，别指望一种方法全包

RQ 管纵向层次，OPQ 消费 RQ 丢弃的残差管横向区分。ICR 68% → 92%。而且层数要克制 —— OPQ 加到 4 层反而暴跌。

02

均衡聚类只在最后一层做

为了追利用率在所有层做 balanced kmeans，会导致层次聚类崩塌，指标全面倒退。粗粒度层要让它自然聚。

03

多模态不是越多越好

109M 的文本编码器打赢 2B 的多模态模型。正确姿势是先用 VLM 把多模态翻译成关键词，再统一文本编码。

04

推理放输入端有用，放输出端有害

在异质符号空间（SID vs 文本）里让小模型显式生成 CoT，HR@10 直接腰斩。这个坑值得记牢。

05

信息不对称自蒸馏是极高性价比的工具

同一套权重、只改输入、只加一个 KL 项，就能把「有特权信息时的能力」压进「没有特权信息时的权重」。学生甚至能超过老师。

06

输出有结构时，advantage 就该有结构

SID 是 coarse→fine 的因果链，给整条序列同一个 advantage 就是浪费信号。逐位置归一化 + 前缀门控，还顺手替代了 clip。

贯穿两篇论文的一条主线

把「结构」显式地告诉优化过程 —— 商品有层次结构，所以 SID 要分层； SID 有因果结构，所以 advantage 要分位置；推理有信息结构，所以蒸馏要造不对称。 每一处收益，都来自把领域里本来就存在的结构，翻译成了训练目标的一部分。

论文自陈的三个待解方向：① 长尾 query 交互太少，需要更好的 beyond-logs 训练策略； ② 视频、直播、商品三种异质内容如何共用一套 SID；③ 走向 agentic search 所需的实时在线学习机制。
