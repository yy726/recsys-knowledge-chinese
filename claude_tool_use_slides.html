01 · 核心概念

什么是工具使用？

工具使用（Tool Use）让 Claude 能调用你定义的函数，或 Anthropic 提供的内置工具。Claude 会根据用户请求与工具描述自主判断是否调用、调用哪个、传什么参数，返回结构化调用请求，由你的程序或 Anthropic 服务端执行。

🖥️ 客户端工具 Client Tools

  • 在你的应用中执行
  • Claude 返回 stop_reason: tool_use
  • 你执行操作后回传 tool_result
  • 含自定义工具 + Anthropic 预置 schema（bash、text_editor、computer_use、memory）

☁️ 服务端工具 Server Tools

  • 在 Anthropic 基础设施上执行
  • 结果直接返回，无需你写执行代码
  • 含 web_search、web_fetch、code_execution、tool_search、MCP 连接器等

02 · 工作原理

工具调用的完整循环

1

发送请求 + 工具定义

在 tools 参数中声明可用工具的 name / description / input_schema

2

Claude 返回 tool_use

stop_reason:"tool_use"，内含调用的工具名与参数 input

3

执行工具

你的程序运行真实逻辑（查数据库、调 API、写文件等）

4

回传 tool_result

以新的 user 消息发送 tool_result，用 tool_use_id 对应

5

循环至完成

重复 2-4，直到 stop_reason 变为 end_turn 等终止状态

⚠️ 关键点：Claude 从不直接执行代码，它只产出结构化请求；驱动整个循环、真正执行操作的永远是你的应用。

03 · 定义工具

Define Tools：Schema 与最佳实践

Schema 四要素

字段说明
name工具标识（正则 ^[a-zA-Z0-9_-]{1,64}$）
description详细说明用途、使用/不使用场景
input_schemaJSON Schema 定义参数
input_examples（可选）示例输入，帮助理解用法

最佳实践

  • 描述要极其详细（建议 3-4 句起）
  • 复杂工具用 input_examples 辅助
  • 相关操作合并为一个工具 + action 参数
  • 用服务名做命名空间前缀（如 github_list_prs）
  • 返回结果只保留高信噪比信息，用稳定标识符

04 · 处理结果

Handle Tool Calls：格式规则与安全

格式硬性规则

  • tool_result 必须紧跟对应的 tool_use
  • user 消息中 tool_result 必须排在 text 之前
  • assistant 与 user 之间不能插入其他消息
  • 失败时设置 is_error: true

⚠️ 安全提醒

把网页、邮件、外部 API 等不可信内容放入 tool_result 块中，不要放进 system 或普通 text 块，以防间接提示注入（prompt injection）攻击。

💡 SDK 提供 Tool Runner，可自动完成解析 tool_use、格式化结果、错误处理与重试，简化手动实现。

05 · 并行调用

Parallel Tool Use：并行工具调用

Claude 可以在一次回复中返回多个 tool_use 块；关键规则是：所有对应的 tool_result 必须放在同一条 user 消息中一起返回。

何时并行 / 何时顺序

  • 并行：无副作用的独立读操作、多方查询
  • 顺序：有副作用的写操作、依赖前序结果、共享状态

控制开关

  • tool_choice:{type:"auto", disable_parallel_tool_use:true} → 最多调用一次
  • tool_choice:{type:"any"} → 必须恰好调用一次
  • 系统提示中加「只批量执行相互独立的调用」可减少误并行

06 · 服务端工具

Web Search Tool：联网搜索

让 Claude 获取知识截止日期之后的实时信息，回答附带引用来源。

关键参数

  • max_uses 限制单次请求搜索次数
  • allowed_domains / blocked_domains 域名白/黑名单
  • user_location 按城市/地区/时区本地化结果

计费与生效场景

  • $10 / 1000 次搜索 + 常规 token 费用
  • 适合：新闻时事、实时价格、组织/人物近况
  • 不适合：数学常识、创意写作、纯分析已有内容

07 · 客户端工具

Text Editor Tool：文本编辑器工具

让 Claude 直接查看、创建、编辑文本文件，用于调试代码、重构、写文档、生成测试。工具名固定为 str_replace_based_edit_tool。

支持的命令

命令作用
view查看文件/目录内容
str_replace精确替换指定文本
create创建新文件
insert在指定行插入文本

实现要点

  • 路径校验，防止目录穿越攻击
  • 修改前建议创建备份
  • str_replace 必须保证唯一匹配
  • 可选 max_characters 控制大文件截断

09 · 延伸对比 & 总结

对比视角：OpenAI 的对话状态管理

OpenAI：三种维护对话状态方式

  • 手动管理上下文：自行拼接完整 messages 数组，简单但历史随轮次增长
  • Conversations API：服务端持久化会话对象，代码更干净，但引入外部依赖
  • previous_response_id 链式引用：传入上一响应 ID 延续上下文，适合简单问答链

与 Claude 工具循环的差异

  • Claude 的多轮工具调用本质上仍是显式消息数组拼接（tool_use ↔ tool_result 严格配对）
  • 两家都强调：上下文越长，token 消耗与费用越高
  • 共同点：都需要对「历史记录如何传递」做工程取舍

📌 总结：工具使用把 Claude 的判断力和外部世界的执行力连接起来——你负责定义边界（schema）、执行动作、传回结果，Claude 负责推理「何时、如何」调用。
